# Image export and cache

SQLite collections can download supported images independently through `media-db --db <file>`, using the same extractor, URL checks, cookies, cache, and downloader described here. Durable image files and per-image checkpoints live beside the database; `export-db` copies verified files into portable bundles offline. See [SQLite image collection](11-sqlite-collection.md#independent-image-collection). The existing JSON `media --input` workflow remains supported.

Implemented **2026-11-05**, with synthetic HTTP and filesystem coverage. The historical [media experiment](02-http-protocol.md#7-images-and-other-media) established a separate media cookie and one JPEG response; it did not establish universal media discovery. Inspection of saved source exports also found inline `https://us-api.asm.skype.com/v1/objects/{id}/views/imgo` URLs alongside opaque `amsreferences` strings. At initial implementation, no new live authenticated image export or login-cookie capture had been performed.

Updated **2026-11-06** to save text before images and support a separate media pass over saved archives. Failure, cancellation, retry, refresh preservation, and concurrent-update behavior have synthetic coverage; this change adds no new live Teams API evidence.

Updated **2026-11-11** after an authorized browser/HTTP investigation of two inline images whose archive sources used `id-prod.asyncgw.teams.microsoft.com`. Both object IDs matched loaded browser images on `experimental-api.asm.skype.com` under an account namespace. Direct HTTP replay of a browser-observed image succeeded using only its matching `skypetoken_asm` cookie; replay without credentials returned 401. The same image also succeeded without the namespace using the application's existing saved experimental-host cookie: HTTP 200, 84,055-byte JPEG with matching signature/end marker, no redirect. This establishes the narrow mapping below for the sampled account and image; it does not establish other regional hosts, all media, or login-cookie renewal. No archive, credential, or normal cache was modified by those probes.

## Export contract

`export` saves `chat.json` and, by default, `chat.md` as soon as the selected window's history is collected. JSON initially marks media `not-downloaded`; Markdown contains image placeholders. Supported images are then downloaded by default, and the saved manifest and Markdown links are updated. `--no-media` skips that second phase. `teams media --input <saved-json>` performs the media phase later without any directory, profile, or history requests. It requires credentials matching the archive's `accountId`, supports `--credentials` and `--refresh-media`, and regenerates sibling Markdown unless `--no-markdown` is supplied. Existing sibling Markdown is replaced, so use that flag to preserve manual edits.

`--refresh-media` explicitly bypasses default cache reuse and cannot be combined with export's `--no-media`. Only HTML messages are parsed for `<img src>`; literal Text messages stay literal. Parsing uses [Bun HTMLRewriter](https://bun.sh/docs/runtime/html-rewriter), including entity decoding and quoted/unquoted attributes.

Supported URLs use HTTPS on exactly `us-api.asm.skype.com` or `experimental-api.asm.skype.com`, with `/v1/[namespace/]objects/{object}/views/imgo`. Namespace and object segments use letters, numbers, underscores, or hyphens. URLs containing user information, query strings, fragments, other hosts, or other views are unsupported. Opaque references are never converted into guessed URLs. References without inline images count as unsupported; HTML images with unsupported destinations count individually. When inline images exist, opaque reference arrays are retained without separately interpreting their entries.

The additional source form `https://id-prod.asyncgw.teams.microsoft.com/v1/objects/{object}/views/imgo` uses the verified translation to `https://experimental-api.asm.skype.com/v1/objects/{object}/views/imgo`. Only this exact regional origin and unnamespaced path are accepted; the same user-info/query/fragment restrictions apply. `imageSourceUrl` recognizes these sources while preserving their identity, and `imageUrl` continues to validate only actual Skype ASM cookie destinations. Source records are never rewritten, and logical keys hash the original source URL so Markdown links remain correct. Smoke fixture/history image discovery uses the same source recognizer and delegates translation to the real downloader.

JSON remains version 1, preserves source messages, and adds a media manifest:

- `status` is `complete` after all references are handled, or `partial` when a published media pass has unsupported references or failed downloads. This is separate from completed history retrieval. `--no-media` uses `not-downloaded`.
- `cacheHits`, `downloaded`: distinct supported image keys reused or fetched, including explicit refresh results. `cacheHits` includes both local reuse without a request and reuse after an HTTP 304; terminal summaries report these separately.
- `unsupported`: unresolved reference count.
- `images`: message ID, logical key, relative local path, byte length, SHA-256 digest, and media type. Repeated appearances of one image in a message share one mapping.

Each export uses a dedicated directory containing `chat.json`, optional `chat.md`, and `media/<content-sha256>.<extension>`. The source-URL logical key remains in the manifest; content-based filenames keep old manifest paths valid when a later refresh fails. Older version-1 archives using logical-key filenames remain readable. Export `--out <directory>` chooses this folder; the default layout groups each period under `exports/<chat-label>/`. Default `--last 1d` exports use a stable local `YYYY-MM-DD` period and refresh that day's verified archive; other windows remain timestamped snapshots. Private directories and files use modes 700/600 when created. No image directory is created for an empty supported set. Existing snapshot and explicit `--out` directories are refused before retrieval. After history retrieval, a snapshot exclusively creates its directory. Default daily refreshes validate the saved account/chat/window and hold the archive reservation during history retrieval, text publication, and media download. Failed history retrieval preserves the saved daily bundle. Each successful daily refresh starts a new current media manifest and reuses the account-scoped image cache; unreferenced old files are retained.

Failure before initial JSON publication removes this attempt's directory. Each image copy is published through a temporary file and atomic rename. An individual download failure leaves later images eligible for processing. If the pass saves any images, it publishes a partial manifest with their links and retains verified previous links for images that failed to refresh. An entirely failed pass, cancellation during downloads, or a storage error during downloads leaves the previous manifest and Markdown in place. JSON is replaced first, then generated Markdown, using two atomic writes. A Markdown update failure keeps the new manifest and old Markdown, and retrying the media command repairs the links using the cache. Old or unreferenced images remain on disk. History pagination still has no durable checkpoint.

Media passes exclusively create an adjacent `<input>.media.lock` directory and release it on success, handled failure, or cancellation. A concurrent pass for the same archive is refused. A hard crash may leave that lock: after verifying that no updater is running, inspect and remove the empty lock directory before retrying. The same lock coordinates default daily history refreshes and media passes through `withArchiveLock`; daily export calls the already-locked media core. It does not coordinate arbitrary external edits to JSON or Markdown.

Source messages, history metadata, and `completedAt` remain unchanged during media updates. `mediaUpdatedAt` records the last published media pass. Archive `requests` add each published pass's transport attempts and retries, including attempts for failed images in a published partial pass. Terminal summaries report attempts for unpublished passes. The media manifest's cache/download counts describe the latest published pass.

Unsupported media does not fail history export: it is explicitly partial in the media manifest, counted in the image summary on stdout, and uses rendering placeholders. Image summaries go to stdout even on failure; actual download/authentication/write failures are reported on stderr and fail the command. Initial Markdown failure keeps JSON and stops before media, allowing offline conversion or a later media pass.

## Credentials and HTTP

The optional version-1 credential field `mediaCookies` maps each allowed origin to the cookie **value**, without the `skypetoken_asm=` prefix. `login` asks its own browser jar for cookies applicable to each origin's `/v1/` URL after normal profile/directory/history verification; only unexpired or session `skypetoken_asm` cookies are retained. No unrelated cookies are persisted. An ordinary login without media cookies still succeeds with a diagnostic. `login --wait-for-media` waits when none are available, asking the user to open an image-containing chat. A successful supported image GET triggers a cookie lookup for that exact URL; reusable cookies must be scoped to `/`, `/v1`, or `/v1/`. The login timeout and cancellation still apply. An uncached image without its origin's cookie fails with instructions to run `login --wait-for-media` or use `--no-media`.

Cookie presence is not an image-access verification. Export supplies only `Cookie: skypetoken_asm=<value>` to the matching destination origin and exact validated download URL. Translated regional sources use only the experimental-host cookie; neither media cookies nor history/profile/directory credentials are sent to `id-prod.asyncgw.teams.microsoft.com`. The credential schema and login cookie-origin allowlist remain the two Skype ASM origins. History/profile/directory credentials are never sent to media hosts. Media cookies are never sent to Teams history routes. Redirects are refused, including same-origin redirects. Credentials, source URLs, and response bodies are excluded from new media metadata and diagnostics; canonical source messages remain unchanged and may themselves contain source URLs.

Media uses the shared Ky retry policy, cancellation, timeouts, and attempt counters. `media` is a separate request-purpose counter. Missing credentials, HTTP 401, and HTTP 429 after retries suppress subsequent requests to the same origin for the invocation. Normal cache hits can still be reused, and other origins are processed. HTTP 403 is treated as an individual image failure because access can be object-specific. Downloads are sequential and buffer at most one response at a time, capped at 50 MiB after decompression. HTTP 200 is required for a fetched image. JPEG/PNG/GIF/WebP content types must match basic signatures and container endings/lengths. This is not a full image decode or a guarantee against every malformed container. SVG, HTML login responses, empty bodies, partial-content responses, and obvious truncation are rejected.

## Cache and refresh

The default root is `$XDG_CACHE_HOME/teams-chat-download/media`, falling back to `~/.cache/teams-chat-download/media` for unset, empty, or relative XDG values. A SHA-256 digest of the stable account label selects an account directory. A logical key hashes the complete original supported source origin and path, including namespace, object ID, and `imgo` representation, before regional translation. Query-bearing URLs are unsupported rather than stripping unknown version or authentication parameters. Different source hosts remain separate keys even when they resolve to the same download URL.

Each key has an independent versioned JSON metadata file; bodies are named by content digest and extension. Metadata includes key, type, size, digest, and optional ETag/Last-Modified. Writes use private temporary files and atomic rename, publishing the complete body before metadata. Independent entries avoid a shared index and its lost-update race. Concurrent readers see complete old or new entries; concurrent refreshes use the last published entry. Superseded bodies are retained; cache eviction is not implemented.

A hit requires valid metadata, a present body, matching byte length and digest, and matching type/signature checks. Complete hits perform no HTTP request, including no HEAD, and require no current media cookie. Missing/corrupt entries miss the cache. Other filesystem errors fail explicitly. Repeated logical keys download once per invocation. Local copies keep export contents independent of later cache changes or deletion.

Explicit refresh sends `If-None-Match` when an ETag exists, otherwise `If-Modified-Since` when Last-Modified exists. Without a validator, refresh is unconditional. A `304` reuses the already loaded, verified body; deleting the cache body while the request is in flight cannot remove those bytes. A `304` without a valid cached body fails. Missing/corrupt bodies start with an unconditional request. A `200` replaces the mapping only after validation and complete cache publication; a failed refresh keeps the old entry usable. Default reuse prioritizes avoiding repeat requests and can retain stale remote images until explicit refresh.

Per-image progress distinguishes `reused from local cache`, `revalidated with Teams: HTTP 304; reused cached bytes`, and `downloaded: HTTP 200`. The image summary counts local reuse, revalidated reuse, and downloads separately, including on failure. Progress is emitted after each image is saved to the export; refresh requests run sequentially, so revalidated images can take longer than local reuse even though their bytes are not downloaded again.

## Offline rendering and limits

The archive reader validates version-1 manifests and image fields. Image paths must be `media/<hash>.<extension>`; absolute and parent-traversal paths are rejected. Markdown matches local images by source message identity and normalized source-URL digest, so hidden or removed HTML nodes cannot shift later image mappings. Alternative Markdown destinations rebase links to the original image directory without network requests or file copying.

Supported formats and paths do not imply original-upload fidelity, all-image discovery, video/file support, stickers/cards/replies coverage, signed-URL handling, deleted-image recovery, cookie renewal, or support for every region. The November 11 direct HTTP probe validates one cold image response with saved credentials; end-to-end live CLI publication, live login-cookie capture, and behavior on other accounts remain to be checked through ordinary authorized usage.

### Standard Teams emoji

Images marked `itemtype="http://schema.skype.com/Emoji"` with nonblank `alt` are text, rendered with Markdown escaping and excluded from unsupported-media counts. Recognition does not broaden authenticated download destinations. Custom emoji and images without usable emoji text retain normal attachment handling. Emoji alone do not suppress warnings for opaque `amsreferences` attachments. Original HTML remains intact in JSON.
